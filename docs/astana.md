# География и модель Астаны

3D-сцена использует снимок OpenStreetMap от **23 сентября 2026 года**, включённый в `app/src/traffic/data/astana.json`. Область охвата: широта 51.079–51.175, долгота 71.380–71.493 — центральная часть города от EXPO на юге до правого берега на севере. Это ограниченный участок, не вся Астана.

После клонирования достаточно обычного `docker compose up --build -d --wait`. Снимок входит в JS-сборку; 3D-сцене не нужны ключи карт, внешние геосервисы или изменения `.env`. Leaflet-карта в аналитике отдельно загружает тайлы OpenStreetMap.

## Что взято из геоданных

- Основные дороги, их названия и изгибы: 641 узел, 1045 участков после упрощения.
- Метки мостов и осевые линии Есиля/Ишима и притока Акбулак. Ширина воды и высота мостов заданы условно; контуры берегов не являются геодезическими данными.
- Координаты Байтерека, Хан Шатыра, Акорды, Дворца мира и согласия, Астана Опера и Хазрет Султан из OSM/Nominatim. Идентификаторы исходных объектов сохранены в `data/landmark-sources.json`. Положение EXPO «Нур Алем» задано приближённо.

Расположение бульвара Нуржол связывает Хан Шатыр, Байтерек и Акорду. Парковые зоны, фонтаны и набережные оформлены вручную. Обычная застройка генерируется с фиксированным seed вдоль дорог с исключением воды, парков и площадей достопримечательностей; это не контуры реальных домов. На левом берегу больше высотных зданий, на правом — невысокой застройки. Все семь моделей достопримечательностей созданы в коде и передают общий силуэт, с преувеличенными размерами для игровой камеры.

Названия и взаимное расположение ориентиров сверялись с [Visit Astana](https://www.visitastana.kz/ru/about-city/what-to-see/) и [описанием комплекса Акорда](https://mirror.akorda.kz/kz/republic_of_kazakhstan/akorda). Эти страницы не являются источником 3D-ресурсов.

## Упрощение дорожного графа

Географические координаты переводятся в локальную плоскость относительно 51.128, 71.430. Одна единица сцены соответствует 8 географическим метрам; ось X направлена на восток, Z — на юг. Высоты и размеры транспорта имеют отдельный игровой масштаб.

Импортёр объединяет последовательные участки без развилок, сохраняя полилинии, затем группирует близкие узлы в пределах 48 метров при совпадении `layer`. Для параллельных связей между одной парой узлов сохраняет более короткую геометрию и идентификаторы исходных ways. Остаётся крупнейшая связная компонента. Мелкие почти коллинеарные точки удаляются. Участки с обеих сторон границы отсекаются; это не полноценный GIS-клиппинг.

Сеть двусторонняя: теги `oneway`, ограничения поворотов, фактическое число полос и расписания не используются. Маршруты автобусов и ЛРТ построены для демонстрации. Геометрия реальна, транспортные потоки синтетические. Пять зон влияния мер условные и сохраняют районы из задания; административные границы не импортируются. Параметры движения и масштаб времени описаны в [модели транспорта](traffic.md).

## Обновление снимка

Обновление — отдельная ручная операция разработчика; приложение её не запускает. Текущий снимок достаточен для демо. При необходимости один раз выполните этот запрос в [Overpass Turbo](https://overpass-turbo.eu/), затем сохраните ответ через **Export → raw data** в `/tmp/astana-roads.json`:

```text
[out:json][timeout:40];
(
  way[highway~"^(primary|secondary|tertiary|trunk|primary_link|secondary_link|tertiary_link|trunk_link)$"](51.079,71.38,51.175,71.493);
  way[waterway=river](51.079,71.38,51.175,71.493);
);
out geom;
```

Из корня репозитория, с Node 24:

```bash
node scripts/import-astana.mjs /tmp/astana-roads.json
cd app
npm run test:traffic
npm run build
```

Импортёр работает без сети. Ответ с `remark` отклоняется как неполный. Не удаляйте метаданные `source`, `license`, `attribution` и `timestamp`. После обновления проверьте географию визуально и зафиксируйте новый JSON в Git вместе с изменёнными метаданными. Число узлов может измениться, поэтому при необходимости обновите документацию.

Публичные экземпляры Overpass могут быть загружены. Не опрашивайте их при каждом запуске или в цикле; при ошибке продолжайте пользоваться готовым снимком. О сервисе: [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API).

## Проверка

`npm run test:traffic` проверяет связность графа, корректность кратчайших путей независимым алгоритмом, положительные длины сегментов, криволинейную геометрию и работу транспорта. `npm run test:e2e -- e2e/city.spec.ts` проверяет WebGL, навигацию к ориентирам, атрибуцию, мобильный экран, общий план и режим 2D. Эти браузерные тесты не вызывают LLM.
